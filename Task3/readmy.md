Проблемы текущего решения
   Синхронные REST API вызовы

    Сервисы core-app и ins-comp-settlement зависят от синхронных запросов к ins-product-aggregator.
    
    При увеличении числа страховых компаний (с 5 до 10) время ответа может вырасти в 2 раза.
    
    Ошибки или задержки у одной из страховых компаний приведут к задержкам или сбоям во всей системе.

Периодическое обновление данных

    core-app обновляет данные каждые 15 минут, что может приводить к устаревшим данным.
    
    ins-comp-settlement обновляет данные раз в сутки, что критично для актуальности информации.

Дублирование данных

    Оба сервиса хранят локальные копии продуктов и тарифов, что усложняет синхронизацию.
    
    При изменении данных в ins-product-aggregator изменения не сразу попадают в core-app и ins-comp-settlement.

Проблемы с масштабированием

    При добавлении новых страховых компаний нагрузка на ins-product-aggregator возрастёт.
    
    Сейчас агрегатор делает последовательные запросы, что увеличивает общее время ответа.

    Ежедневный выгруз данных из core-app в ins-comp-settlement

Используется синхронный REST API, что может приводить к таймаутам при большом объёме данных.

Предлагаемые решения
1. Переход на Event-Driven архитектуру
    Использовать Kafka (или другой брокер сообщений) для асинхронного обмена данными.

Что изменить:

ins-product-aggregator публикует обновления продуктов в топик Kafka products-updates.

core-app и ins-comp-settlement подписываются на этот топик и обновляют свои локальные кэши в реальном времени.

ins-comp-settlement вместо ежедневного REST API запроса получает события о новых страховках через топик policy-created.

Преимущества:
✔ Отказ от синхронных вызовов → снижение задержек.
✔ Данные обновляются в реальном времени.
✔ Устойчивость к ошибкам (если Kafka доступен, сообщения будут доставлены).

2. Использование паттерна Transactional Outbox
    Применять для гарантированной доставки событий.

Как это работает:

Когда ins-product-aggregator получает новые данные от страховых компаний, он:

Сохраняет данные в БД.

Записывает событие в таблицу outbox_events (в той же транзакции).

Отдельный процесс (Debezium) отправляет события в Kafka.

Преимущества:
✔ Гарантированная доставка (нет потерь данных).
✔ Согласованность данных (если запись в БД прошла, событие будет отправлено).

3. Оптимизация запросов к страховым компаниям
    Заменить последовательные запросы на параллельные.

ins-product-aggregator делает асинхронные вызовы ко всем страховым компаниям

Результаты агрегируются и отправляются в Kafka.

Преимущества:
✔ Уменьшение времени ответа (не ждём ответа от каждой компании по очереди).
